1. Comprensión del negocio · R10¶

El destinatario hipotético es la Secretaría Distrital de Salud de Bogotá. La decisión explorada es cómo priorizar evaluaciones bajo errores asimétricos. No se recomienda usar este modelo para asignar recursos reales: falta un resultado observado válido.

La pérdida de entrenamiento es propia de cada algoritmo; la métrica de selección es el costo simulado por registro (5 FN + FP) / n, con Alcohol=1. La razón 5:1 es un supuesto académico, no un costo oficial. Se evalúan además razones 1, 2 y 10. La referencia es un DummyClassifier. El éxito experimental consiste en reducir costo frente a esa referencia; no se promete que suceda. Sensibilidad, precisión, especificidad, F1, ROC-AUC y PR-AUC complementan el costo. No hay capacidad operativa real documentada.

Riesgos: confundir una etiqueta generada con un diagnóstico, estigmatización territorial, sesgo por atributos sensibles, falta de representatividad y registros dependientes.

3. Preparación y diseño experimental · R12¶

Se conserva la idea de normalizar marcadores y codificar variables, con cambios necesarios:

  1. No se eliminan categorías de sexo por escasez; el tamaño final ya no es 101.497.
  2. No se imputan sexo o etnia aleatoriamente por localidad. Se conserva la ausencia como categoría.
  3. Las reglas de simulación son fijas por fila, sin aprender distribuciones del conjunto. Un valor desconocido aporta cero al incremento correspondiente. La probabilidad base 0,70 y los incrementos se heredan como supuestos, no como estimaciones epidemiológicas verificadas.
  4. Se separa 20% de prueba antes de ajustar transformaciones. Del 80% restante se reserva 25% para el umbral: 60% total para CV/modelos, 20% para umbral y 20% para prueba.
  5. Toda transformación de X está dentro del Pipeline. Las categorías one-hot se aprenden en cada fold; el número de columnas resultante no se fuerza a 176.

Se excluyen SUSTANCIA, PROB_ALCOHOL, Alcohol, CASOS y la vía de llegada a tratamiento. Tiempo no se usa como predictor para reproducir el simulador heredado; no se afirma que carezca de relevancia real. No se aplican SMOTE ni pesos de clase: el costo asimétrico se aborda en la regla de decisión para no alterar innecesariamente la interpretación probabilística.

# Transformación determinista: no ajusta estadísticas y conserva filas e índices.
def normalizar_predictoras(frame):
    salida = frame.copy()
    for col in categoricas:
        texto = salida[col].astype('string').str.strip()
        texto = texto.mask(texto.str.lower().isin(marcadores))
        salida[col] = texto.astype(object).where(texto.notna(), np.nan)
    for col in binarias:
        salida[col] = salida[col].astype('string').str.strip().str.upper().map({'SI': 1.0, 'NO': 0.0})
    return salida

def crear_pipeline(modelo):
    # Las estadísticas aprendidas y el vocabulario de categorías quedan dentro de cada fold.
    categorias = Pipeline([
        ('faltantes', SimpleImputer(strategy='constant', fill_value='Desconocido')),
        ('onehot', OneHotEncoder(handle_unknown='ignore', sparse_output=True))])
    sitios = Pipeline([('faltantes', SimpleImputer(strategy='constant', fill_value=-1.0))])
    columnas = ColumnTransformer([('categorias', categorias, categoricas),
                                  ('sitios', sitios, binarias)], sparse_threshold=1.0)
    return Pipeline([('normalizar', FunctionTransformer(normalizar_predictoras)),
                     ('columnas', columnas), ('modelo', modelo)])

# El costo de selección usa un umbral fijado antes de cualquier validación.
def puntuacion_costo(estimador, x, y):
    prob = estimador.predict_proba(x)[:, 1]
    pred = prob >= UMBRAL_REFERENCIA
    return -float(np.mean(C_FN * ((np.asarray(y) == 1) & ~pred) +
                          C_FP * ((np.asarray(y) == 0) & pred)))

# Comprobaciones de invariantes sobre entrenamiento: no requieren abrir prueba.

4. Modelado comparativo · R13 y R14¶

Se comparan Dummy (prior), regresión logística, árbol y bosque aleatorio usando los mismos cinco folds estratificados y el mismo costo. Las búsquedas son pequeñas y declaradas, acordes con el presupuesto académico; no constituyen optimización exhaustiva. La familia final es la de menor costo CV promedio, incluidos los candidatos Dummy. Empates favorecen menor desviación y menor complejidad. Se conserva el ajuste del ganador sobre desarrollo (60% total).

El umbral teórico 1/6 se usa solo como referencia de selección: sería óptimo si las probabilidades fueran correctas y los costos completos fueran los declarados. La reserva independiente permite ajustar el umbral empíricamente sin usar prueba. La CV reutilizada para selección puede ser optimista; la estimación final independiente se reporta al final.

5. Evaluación de desarrollo y selección del umbral · R13–R17¶

La reserva de umbral no ajusta coeficientes ni árboles. Se elige el umbral que minimiza el costo 5:1 en una rejilla 0–1 de paso 0,01 más 1/6. En empate se prioriza sensibilidad. No se vuelve a entrenar el modelo después: hacerlo cambiaría la escala de probabilidades. Las métricas de esta reserva son de selección, no una validación independiente del umbral. Se informa también la fracción de alertas, para mostrar la carga de atención hipotética. Los escenarios de costo no constituyen precios ni compromisos de capacidad reales.

R15–R17: se realiza diagnóstico descriptivo de segmentos sobre esta reserva. No se impone clustering: no es necesario para el objetivo supervisado simulado y no valida perfiles reales. No se inventa evidencia histórica de retos entregados.

# Función común para métricas; la etiqueta positiva siempre es Alcohol=1.
def medir(y, prob, umbral, costo_fn=5.0):
    pred = np.asarray(prob) >= umbral
    tn, fp, fn, tp = confusion_matrix(y, pred, labels=[0, 1]).ravel()
    return {'umbral': float(umbral), 'n': len(y), 'TN': int(tn), 'FP': int(fp),
            'FN': int(fn), 'TP': int(tp), 'costo': float((costo_fn * fn + fp) / len(y)),
            'sensibilidad': recall_score(y, pred, zero_division=0),
            'precision': precision_score(y, pred, zero_division=0),
            'especificidad': float(tn / (tn + fp)) if tn + fp else None,
            'f1': f1_score(y, pred, zero_division=0), 'accuracy': accuracy_score(y, pred),
            'auc': roc_auc_score(y, prob) if len(np.unique(y)) == 2 else None,
            'pr_auc': average_precision_score(y, prob) if len(np.unique(y)) == 2 else None,
            'brier': brier_score_loss(y, prob), 'fraccion_alertas': float(pred.mean())}

Evaluación final única en prueba¶

La familia, sus hiperparámetros y el umbral ya están congelados. Esta celda realiza una única predicción probabilística en X_test y calcula todas las métricas a partir de ella. El baseline constante usa la prevalencia de desarrollo, sin ajustarse a prueba. Las bandas bootstrap describen incertidumbre condicional a este ajuste; no incluyen incertidumbre de otras semillas, simuladores, dependencias de eventos ni cambios de población. No se permite volver a seleccionar modelos o umbrales después de observar estas cifras.

6. Despliegue, límites y gobernanza · R18¶

El entregable es un experimento reproducible para discusión académica, sin despliegue asistencial. Una ventaja frente a Dummy solo muestra aprendizaje del generador sintético. La reserva de umbral puede demandar evaluar una proporción muy alta de registros; no equivale a viabilidad. La variabilidad CV describe estabilidad entre estas particiones, no validez del resultado real. Una brecha entre costo de entrenamiento y CV sugiere sobreajuste; ambos altos sugieren capacidad insuficiente o ruido irreducible. No hay descomposición causal formal de sesgo-varianza.

Antes de un piloto real se requieren etiquetas observadas multietiqueta cuando corresponda, verificación de unidad de análisis, partición temporal y por persona, costos acordados y capacidad de atención. Responsables propuestos (no asignaciones históricas): custodio de datos valida procedencia y permisos; equipo analítico valida estabilidad y sesgos; responsable de salud aprueba el uso y la supervisión humana. En un eventual piloto, revisar mensualmente faltantes, categorías nuevas, deriva y carga de alertas; evaluar sensibilidad y precisión cuando maduren las etiquetas. Suspender ante cambio de definición del resultado, falta de etiquetas confiables, fallo de calidad o perjuicio desigual no resuelto. No tomar decisiones individuales automáticas.
